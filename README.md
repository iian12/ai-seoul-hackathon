# 서울사이 · React + Supabase MVP

서울에서 예산과 생활 우선순위로 동네를 비교하는 로컬 MVP입니다. 기존 LabFlow와 독립된 Vite 프로젝트입니다. 회원가입·결제·매물 중개·길찾기는 포함하지 않습니다.

## 데이터 집계·원천 보완 (2026-11-21)

기존 입력 화면에서 최근 24개월 계약을 비교하도록 내부 집계를 갱신했습니다. 모든 주택유형·면적을 포함하며 상세 원자료는 비공개 SQLite에 보존합니다. 약국 5,474행·병의원 19,466행의 공시 운영시간을 실제 API로 갱신했고, 신규 CCTV·비상벨·상권 API는 기존 키의 활용승인이 필요합니다. [집계 정책·실제 반영 상태·실행 방법](docs/data-update-20261121.md)을 참고하세요.

## 역 도보 접근성 (2026-11-16 추가)

사용자 최종 요청대로 **예산 입력·필터·주거비 계산을 그대로 유지**했습니다. 역 접근성은 직선거리 대신 실제 OSM 보행 도로망의 최단경로를 사용합니다. 현재 452개 법정동에서 경로를 확인했고 15개는 경로 미확인으로 추천에서 제외합니다. 지도에서 선택 지역의 도보 선형과 출입구 인근 종점을 볼 수 있습니다.

[도보 구현·한계·경계/안전시설/안심귀갓길 원천 조사](docs/walking-and-latest-apis.md)를 확인하세요. 일반 길 4.5km/h·계단 0.8m/s의 추정 시간이며 시·종점 보정은 거리·시간에 합산하지 않습니다.

```sh
npm run walking:download
npm run walking:build
npm run walking:apply
npm run walking:test
npm run data:check
```

최초 Python 환경 구성은 위 도보 문서에 안내합니다. 기존 API 키 외의 유료 보행 API 키는 필요하지 않습니다.

## 서울 전체 실자료 연동 (2026-11-16 추가)

서울 전체 정적 원천 수집과 **법정동 코드·이름 매핑, 시설 접근성·예산 공동 분포 집계**를 추가했습니다. 생성한 실제 스냅샷은 앱에서 자동으로 우선 읽습니다. 데이터 모드에서 가상 체험 데이터와 실제 집계 데이터를 구분해 선택할 수 있습니다.

- [수집·집계 결과와 제외 내역](docs/seoul-data-report.md)
- [파이프라인 실행·범위·산식·자료 한계](docs/data-pipeline.md)
- 로컬 실제 스냅샷: `public/data/seoul-snapshot.json`
- 수집 원본·실행 상태·SQLite·상세 QA: Git 제외된 `data/full-seoul/`
- 전체 지역 선택기에서 TOP 3 이외의 법정동도 확인할 수 있습니다.
- Supabase 프로젝트 생성·원격 적재·외부 배포는 아직 하지 않았습니다.

```sh
npm run data:sync
npm run data:check
```

## 실행

Node.js 24 이상을 사용하세요. 저장소 루트에서 다음 명령을 실행하세요.

```sh
npm ci
npm run dev
```

<http://127.0.0.1:5173>에서 ‘예시 예산 넣기’ → ‘내 동네 찾아보기’를 누르면 전체 흐름을 볼 수 있습니다. 개발 서버를 종료하려면 터미널에서 Ctrl+C를 누르세요.

이 저장소에는 원천 데이터와 배포용 스냅샷을 포함하지 않습니다. 별도 설정 없이 내장 체험 데이터로 실행할 수 있습니다. 실자료를 사용하려면 위의 데이터 수집·집계 안내를 따르세요.

### AI 비교 설명 설정

프로젝트 루트의 `.env.server.local`에 `GROQ_API_KEY=발급받은_실제_키`를 설정한 뒤 개발 서버를 다시 시작하세요. 기존 데이터 수집용 키는 유지하고 이 항목만 추가합니다. 이 키는 AI 비교 설명·말로 조건 찾기·화면 안내·음성 인식에 사용하며, 추천 점수와 순위 계산에는 사용하지 않습니다. `VITE_` 접두사를 붙이거나 소스 코드에 키를 넣지 마세요.

Vercel 배포에서는 서버 환경변수 `GROQ_API_KEY`를 설정하고 다시 배포해야 합니다. `npm run preview`와 `npm run serve:public`은 정적 파일만 제공하므로 AI API를 실행하지 않습니다. 로컬 AI 기능은 `npm run dev`에서 확인하세요.

```sh
npm test
npm run build
npm run check:secrets
```

## 구현 범위와 데이터 상태

- 최대 보증금·월세 동시 필터, 가중치 정규화, 프리셋 5종, 결정론적 TOP 3, 지역 상세·출처·기간·모델 표시.
- Leaflet + OSM 지도, 서울 외부 마스크, 구 경계 표시, 지역 마커와 추천 카드 연동. 실제 행정동 경계가 적재되면 `Area.boundary`에 따라 영역 색상 표시를 지원합니다.
- 최소 10건, 전세·기간 밖·잘못된 거래 제외, 필수 지표 결측 제외, 0건·1~2건 결과, 지도 타일 실패 안내, 키보드 입력·추천·상세 열람, 모바일 레이아웃.
- 초기 예산은 비워 두며 0원도 유효한 입력입니다. 입력 단위는 **만원 정수**입니다. 중요도는 원값을 합계 100%로 환산합니다.
- 안전·교통·의료는 서울 전체 대표점 관측값의 백분위(`percentile-v1`, 동점은 평균 순위)로 계산합니다. 교통은 보행 경로 확인 지역만 기준에 포함합니다. 기준 분포는 예산·반경 필터 전에 고정하며 위치 점검도 같은 기준을 보간합니다. 상대 순위 점수이므로 실제 품질이나 거리 차이의 비율을 뜻하지 않습니다. 기존 로컬 스냅샷은 `npm run data:rescore`로 JSON·gzip·위치 점검 기준을 함께 갱신합니다.
- 주거비 점수는 현재 예산에서 다시 계산합니다. 안전·의료와 역 도보/정류소 접근성은 동일 스냅샷의 사전 집계 점수입니다. 소수점 반올림 전 점수 → 예산 적합 비율 → 유효 거래 수 → 지역 코드로 동점을 결정합니다.
- **기본 화면은 검증한 서울 실제 집계 스냅샷을 우선 읽습니다.** 체험 모드를 고르면 가상 값 표시를 유지합니다. 실자료 점수도 생활 품질·안전 보장을 검증한 모델이 아닌 잠정 비교 지표입니다.
- **공공 API 4개 기관의 대표 엔드포인트 8개는 실제 인증 호출 검증에 성공했습니다.** [검증 결과](docs/api-verification.md)를 확인하세요. 전체 API 기능·전체 레코드·좌표계·원천 갱신 주기까지 검증한 것은 아닙니다.
- 정적 입지에 사용하는 12종 원천을 전체 수집하고, 법정동 매핑·시설 접근성·전월세 공동 분포 집계를 반영했습니다. 오래된 안전시설 자료 보완과 점수 모델 타당성 검증은 후속 작업입니다. 거래는 법정동 코드와 이름으로 연결합니다.
- Supabase 프로젝트는 아직 없다는 사용자 선택에 따라 **원격 프로젝트 생성·DB 적용·배포는 하지 않았습니다.** 공개 읽기 클라이언트·RLS 마이그레이션·스냅샷 가져오기 코드를 준비했습니다. 원격 DB 통합 테스트는 미실행입니다.

## 서울 한정

추천 대상·지도·데이터 검증을 서울특별시로 한정합니다. `src/lib/seoul.ts`는 25개 서울 자치구 이름과 서울 구 경계 폴리곤으로 지역 중심점을 검사합니다. 단순 사각형 안에 들어오는 부천·성남도 제외합니다.

서울 25개 자치구와 467개 법정동은 **2026년 11월 9일 기준** 국토교통부 법정구역 전체본을 사용합니다. 11월 18일까지 제공된 변동분에서 서울 변경은 없었습니다. 원본을 WGS84 GeoJSON으로 변환하고 지도용으로 자치구 5m, 법정동 1m 허용오차를 적용해 단순화했습니다. 가상 지역 코드는 `demo-` 접두사로 공식 코드와 구분합니다. [브이월드 법정구역정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=21)

지도 타일은 [OpenStreetMap](https://www.openstreetmap.org/copyright)이며 화면에서 출처를 표시합니다. 오프라인일 때는 배경지도를 볼 수 없지만 추천 목록과 상세는 이용할 수 있습니다. 실자료 모드에서 전체 지역 대표점을 작은 점으로 표시하고, 추천·선택한 법정동은 참고용 경계와 함께 강조합니다. 시설 자체의 개별 마커 레이어는 제공하지 않습니다.

## API 키

이전 `해커톤 주제 선택하기` 대화에서 저장한 기관별 키 4개를 `.env.server.local`에 복사했습니다. 소유자 읽기·쓰기(600) 권한이고 Git에서 제외됩니다. 키 값은 소스·문서·브라우저 번들에 포함하지 않습니다.

```sh
npm run verify:apis
```

검증 스크립트는 서울 전월세·역사·정류소, 심평원 병원·약국, 국립중앙의료원 약국, T-Data 지하철 좌표, 생활안전지도 WMS를 소량 호출합니다. 키·요청 URL·응답 원문을 출력하지 않으며, 인증 정상 코드와 실제 row/item 또는 PNG 시그니처를 검사합니다. 하나라도 확인되지 않으면 종료 코드 1입니다. 결과는 Git 제외된 `data/api-verification.json`에 저장합니다.

WMS는 지도 이미지입니다. 범죄 확률이나 수치 점수로 역산하지 않습니다. 생활안전지도 자료는 [제공처의 공공누리 4유형 조건](https://www.safemap.go.kr/opna/data/dataViewRenew.do?objtId=205)을 별도로 확인해야 합니다. 이번 화면에는 해당 레이어를 배포하지 않았습니다.

## Supabase 연결

원천 전체 적재가 기본 요구사항입니다. [전체 원천 적재 안내](docs/full-raw-supabase.md)에 DB 스키마, 패키지, 재시도, 실제 용량을 정리했습니다. 로컬 패키지 생성과 검증은 완료했고 원격 프로젝트는 아직 없습니다.

1. SQL Editor에서 `supabase/migrations/`의 4개 파일을 파일명 순으로 실행합니다.
2. `.env.server.local`에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 추가합니다.
3. `npm run raw:import -- --upload`로 수집 원본 아카이브와 전체 API 레코드를 적재합니다. 옵션 없는 `npm run raw:import`는 원격 쓰기 없는 dry-run입니다.
4. `npm run snapshot:import -- public/data/seoul-snapshot.json`으로 공개 집계도 별도 적재합니다.
5. `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 설정하고 서버 재시작 후 화면 데이터 안내에서 Supabase 스냅샷을 선택합니다.

원천은 비공개 Storage와 private RLS 테이블에 저장하며, 화면용 공개 집계는 기존 읽기 전용 `housing_snapshots`에 저장합니다. [공식 키 구분](https://supabase.com/docs/guides/getting-started/api-keys)에 따라 Secret key는 서버 전용 파일에서만 사용합니다.

## 검증 기록

- 자동 테스트: 예산 유효성/0원, 가중치, SRS A/B/C 예제, 예산 동시 필터, 9/10건 경계, 전세·오류·기간 제외, 필수 결측, 주거비 재계산, TOP 3 미달, 동점, 상수 분포, 서울 폴리곤, 잘못된 스냅샷 거부.
- TypeScript 검사 및 Vite 프로덕션 빌드.
- 번들에 실제 서버 비밀값이 포함되지 않는지 검사.
- 브라우저: 예산 누락 오류 → 예시 입력 → TOP 3 → 중요도 변경 → 순위 변경 → 상세 근거, 0원 결과, 모바일/데스크톱 확인. 실자료 모드의 467개 법정동 선택기와 TOP 3 외 지역 상세도 확인했습니다.
- 실제 데이터 QA: 전체 원천 건수·고유 기관 ID·서울 좌표·거래 제외 내역·공동 분포 건수 대조, TOP 3의 예산 적합 건수·중앙값을 SQLite 원자료와 대조.
- Supabase SQL 실행과 원격 장애 복구는 프로젝트 부재로 미검증입니다.

원문 요구사항의 미검증 연동과 제안 산식을 그대로 사실로 취급하지 않고, 실제 검증·시연·준비 단계로 구분했습니다.

## 학교·직장 반경 필터

예산 필터와 함께 기준 위치 한 곳과 0.5~20km 반경을 설정할 수 있습니다. OSM 이름·주소를 로컬에서 검색하거나 지도 배경을 클릭해 위치를 지정합니다. 반경은 동네 대표점까지의 직선거리이며 통학·출근 소요시간이 아닙니다. [구현·출처 설명](docs/location-filter.md)을 참고하세요.

원천 CSV의 GitHub 보관 대안은 [용량·Git/LFS/Releases 비교](docs/github-raw-csv.md)를 참고하세요. 현재는 크기 확인까지 진행했으며 GitHub 업로드는 하지 않았습니다.

## 전세·월세 선택

[전세 추천 구현·검증](docs/jeonse.md): 월세 1,629,939건과 전세 1,071,773건을 분리 집계했습니다. 전세는 최대 보증금으로 비교하고, 월세·전세 예산을 각각 유지합니다. 학교·직장 반경과 역 도보 모델도 함께 적용됩니다.

### 예산에 맞는 추천 후보와 주거비 점수

월세는 보증금·월세 상한을 동시에 충족한 계약, 전세는 보증금 상한을 충족한 계약이 최소 10건이면 추천 후보에 포함합니다. 필수 지표·보행 경로·선택한 반경 조건은 함께 적용합니다. 동네 전체 중간값이 예산을 넘어도 후보에서 제외하지 않습니다. 주거비 점수는 예산 적합 비율 60%와 동네 전체 중간값 대비 예산 여유 40%로 계산하며, 중간값이 상한을 넘으면 예산 여유는 0점으로 제한합니다. 월세의 예산 여유에는 월세 중간값, 전세에는 보증금 중간값을 사용합니다.

## 데이터 공개·설명 검증·예산 적합도

스냅샷 변경 스크립트는 `scripts/publish-snapshot.mjs`를 통해 JSON, gzip, 위치 시설, 보행 바이너리를 `public/data/releases/`에 묶어 준비합니다. 스냅샷 형식·원천 SQL 대조·시설 점수 기준·바이너리 크기 검증이 모두 끝난 뒤 `current.json` 포인터를 원자적으로 바꿉니다. 검증 실패 시 기존 공개 포인터를 유지합니다. 이전 버전은 열린 화면의 복구를 위해 보존하며 자동 삭제하지 않습니다. 배포에는 `current.json`과 참조하는 releases 파일을 함께 포함해야 합니다. JSON 등 루트 파일은 이전 도구용 호환 사본입니다.

브라우저는 한 번 확인한 공개 버전에서 gzip을 읽고, 네트워크·압축 해제·JSON·스냅샷 검증 실패 시 같은 버전의 JSON을 재시도합니다. 위치 점검도 해당 버전의 시설·보행 자료를 사용하고 추천 스냅샷과 다르면 새로고침을 안내합니다.

AI 설명은 응답 구조·순위·지역명·주어진 숫자·점수 항목·과장 표현을 검사합니다. 검사를 통과하지 못하거나 AI 서버에 장애가 있으면 과거 계약 수치로 만든 기본 설명을 표시합니다. 이는 문장의 모든 의미를 증명하는 검증은 아니며, 기본 설명과 AI 작성 설명을 화면에서 구분합니다.

예산에 맞는 계약이 최소 10건이면 후보에 유지합니다. 카드에 계약 비율과 건수를 표시하고 30% 미만이면 드문 편임을 알립니다. 종합 점수순과 전체 후보의 예산 적합 비율순을 선택할 수 있으며, 동네 전체 중간값과 예산을 충족한 계약의 중간값을 구분합니다. 비율순 정렬은 종합 점수를 변경하지 않습니다.

전체 자동 테스트: `npm run test:all`. 실제 데이터 검증: `npm run data:check`. API 타입 검사: `npm run typecheck:api`.
