# 서울 실자료 수집·매핑·집계

역 도보 접근성을 추가한 현재 모델과 최신 API 조사는 [도보·최신 자료 문서](walking-and-latest-apis.md)에 정리했습니다. 예산 기능은 유지하며, 경로 캐시가 있으면 아래 기초 집계 후 도보 모델을 자동으로 결합합니다.

이 파이프라인은 서울 전체를 대상으로 정적 목록과 공개 전월세 표본을 수집합니다. 실제 적용 결과는 `seoul-data-report.md`와 Git 제외된 `data/full-seoul/report.json`, `aggregation-report.json`에서 확인합니다.

## 실행

```sh
npm run data:sync
npm run data:check
npm test
npm run build
npm run check:secrets
```

서버 전용 `.env.server.local`의 공공데이터포털·서울 열린데이터광장·T-Data 키를 사용합니다. 발급 키를 브라우저로 전달하지 않습니다. 원천별 HTTP 인증 오류·수집 실패는 키나 요청 URL을 출력하지 않습니다.

`data:sync`는 공개 법정동 경계와 현재 연도 공식 일괄 JSON 준비 → 시설 전체 목록 수집 → 전월세 전체 수집·건수 대조 → 집계 순서로 실행합니다. 전월세는 2024~2026년 공개 범위를 기준으로 고정한 수집 작업이며, 예상 총 건수가 바뀌면 확인 없이 일부만 게시하지 않고 중단합니다.

페이지는 `data/full-seoul/<source>/*.json.gz`에 저장합니다. 중단 후 같은 배치를 다시 실행하면 성공 페이지를 재사용합니다. 캐시는 이번 수집의 재현용이며 자동 갱신 캐시가 아닙니다. 새 기준일로 수집하려면 기존 `data/full-seoul`, `data/current-year-bulk.json`을 다른 이름으로 보관한 뒤 새 배치를 시작하고, 공개 범위·건수를 다시 확인해야 합니다.

## 수집 범위

| 원천 | 수집·사용 |
|---|---|
| 서울 전월세 | 공개 3개 접수연도 전체. 2026 일괄 JSON은 연도·건수를 인증 API와 검증; 2024/2025는 인증 API의 모든 페이지 |
| 서울 역사마스터·버스정류소 | 전체 목록을 받은 뒤 서울 경계 내부 좌표만 집계 |
| T-Data 지하철 좌표 | 전체 목록을 대체 원천으로 보관. 역사마스터와 중복 합산하지 않음 |
| 안심귀갓길 시설·경로·서비스 | 세 목록 전체 수집. 시설 코드·WGS84 좌표는 공식 XLSX 명세 확인 |
| 심평원 병원·약국 | 서울 필터의 전체 목록. 약국은 25개 구 분할 수집 후 전체 건수=고유 ID 수를 대조. 기관 ID 중복 제거, 누락·서울 밖 좌표 제외 |
| 국립중앙의료원 약국·병의원·응급기관 | 서울 필터의 전체 목록. 약국 공시 운영시간은 참고 지표; 응급기관은 의료 접근성 집계 |

발급 목록의 모든 API가 독립적인 분석용 원자료인 것은 아닙니다. 국토부 주택유형별 전월세와 서울 전월세는 원천이 겹쳐 중복 수집·합산하지 않습니다. 실시간 버스 도착·길찾기·공휴일·기관별 상세 조회는 이번 정적 입지 집계에 사용하지 않습니다. 전국 CCTV CSV와 5대 범죄 통계는 별도 파일·통계 자료이며, 이 배치의 ‘전체 수집’에 포함하지 않습니다.

생활안전지도 5종은 WMS 이미지 서비스입니다. 전체 사건 좌표·범죄 건수 테이블로 가져올 수 없으며, 이미지를 숫자로 역산하거나 안전 점수에 넣지 않습니다. 이전 대표 호출 검증과 이번 수치 집계를 구분합니다. 공공누리 4유형인 지도 레이어는 공개 화면에 배포하지 않았습니다.

## 지역 매핑

거래의 `CGG_CD + STDG_CD`와 법정동 경계의 `EMD_CD + 00`을 연결하고 **코드·법정동명·자치구명을 모두 대조**합니다. 법정동과 행정동은 다른 단위이므로 거래를 임의로 행정동에 배분하지 않습니다.

법정동 경계와 대표점은 `src/data/seoul-legal-boundaries.json`에 저장합니다. 2026년 11월 9일 기준 전체본과 11월 18일까지의 변동분을 대조했습니다. 대표점 462개를 유지하고 새 경계 밖의 5개는 경계 안 격자에서 외접 사각형 중심에 가장 가까운 점으로 옮겼습니다. 확인되지 않는 거래 코드는 제외 건수와 지역명을 보고서에 남깁니다. [브이월드 법정구역정보](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=NA&dsId=21)

시설은 WGS84 좌표를 검사하고 서울 경계 밖·누락 좌표를 제외합니다. 기관별 고유 ID로 중복을 제거하며, 서로 다른 기관 목록을 단순 합산하지 않습니다. 거리와 반경은 대표점 기준의 Haversine 직선거리입니다.

## 거래 집계

원천 전체는 보관하고 집계에서는 월세·양수 임대료·0 이상 정수 보증금·양수 면적·건물 유형·정상 계약일을 확인합니다. 전세, 잘못된 값, 미래 계약일, 코드·이름 불일치는 사유별로 제외합니다.

SQLite 원자료에서 **법정동 × 보증금 × 월세별 건수**를 묶습니다. 보증금과 월세의 독립적인 주변 분포를 곱하거나 임의의 거래를 생성하지 않습니다. 예산 동시 필터·유효 표본 수·중앙값은 이 공동 분포에서 계산하며, 검증 스크립트가 TOP 3 결과를 SQLite 원자료와 대조합니다.

원천에 고유 거래 ID가 없으므로 동일 조건의 여러 행을 임의 중복 제거하지 않습니다. 표본 건수는 원천 행 단위이며, 고유 주택·고유 계약 수를 보장하지 않습니다. 관리비·현재 공급 매물은 포함하지 않습니다.

## 기초 집계 점수 모델 `seoul-observed-1.0` (역 도보 결합 전)

`E(d,s)=exp(-d/s)`로 정의합니다. 지표별 원점수를 같은 지역 집합의 5~95백분위로 자르고 0~100점으로 정규화합니다. 상수 분포는 50점으로 표시합니다.

- 안전: `0.5 × min(500m 내 관측 CCTV 지점 / 5, 1) + 0.5 × E(관측 안전시설 최단거리, 500m)`.
- 교통: `0.6 × E(역 최단거리, 500m) + 0.4 × E(정류소 최단거리, 300m)`.
- 의료: `0.5 × E(일반 병·의원 최단거리, 500m) + 0.3 × E(약국 최단거리, 500m) + 0.2 × E(응급기관 최단거리, 3000m)`.
- 주거비: 예산 적합 표본 비율 60% + 전체 유효 월세 표본 중앙값 대비 월세 예산 여유 40%. 기존 MVP와 같은 식으로 요청 예산마다 재계산합니다.

원점수·거리·시설 수·정규화 기준·산식을 공개 스냅샷에 저장합니다. 반경·감쇠 상수·가중치는 검증된 생활 품질 모델이 아닌 MVP 설계값입니다. 관측 CCTV는 **공식 코드 302**이고 301은 안심벨입니다. 설치 대수가 불명확한 시설을 임의로 1대로 가정하지 않고 관측 시설 ID의 지점 수를 셉니다.

안전시설은 안심귀갓길에 관측된 2022년 현장 조사 자료(공개 페이지의 갱신 표시는 2023년)이며, 서울 전체 CCTV 보유량이 아닙니다. 목록 밖 시설이 없다는 뜻이 아닙니다. 범죄 확률·안전 보장을 뜻하지 않습니다. 의료기관은 현재 영업·응급 수용 가능 상태를 보장하지 않습니다. 야간 약국 참고 수는 공시 종료시간으로만 계산하며 지정 심야약국 목록과 다릅니다.

## 게시와 장애 처리

필수 원천의 전체 수집 상태와 건수를 확인한 뒤 집계합니다. 잘못된 스냅샷은 공개하지 않고, 검증된 JSON만 임시 파일에서 `public/data/seoul-snapshot.json`으로 원자적으로 교체합니다. 앱은 이 파일을 우선 읽고 실제 데이터임을 표시합니다. 파일이 없으면 명시적인 체험 모드를 유지하며, 오류를 실제 데이터 성공으로 바꾸지 않습니다.

Supabase 프로젝트가 생기면 동일한 JSON을 `snapshot:import`로 적재할 수 있습니다. 모델 버전 확장 마이그레이션도 포함했습니다. 현재 원격 Supabase 적용과 배포는 하지 않았습니다.
