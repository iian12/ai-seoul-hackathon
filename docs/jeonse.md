# 전세 추천 추가

2026-11-16 로컬 구현·검증. 원천 추가 다운로드 없이 수집 완료한 서울 전월세 2,701,942건을 다시 집계했습니다.

- 월세 1,629,939건, 전세 1,071,773건이 거래/매핑 검증을 통과했습니다. 월세 유효 표본과 기존 추천 결과는 유지됩니다.
- 원천 거래유형이 전세이고, 월세 0원, 보증금 양수, 면적·주택유형·계약일 정상, 서울 법정동 코드·이름이 일치하는 행만 전세 집계에 포함합니다. 원천은 필터링/삭제하지 않고 파생 집계에서만 제외합니다.
- SQLite의 기존 `rental` 테이블은 월세로 유지하며 `jeonse` 테이블에 전세를 분리합니다. 공개 스냅샷에는 동별 `jeonseGroups: [{depositKrw,count}]`를 추가했습니다. 같은 보증금의 빈도로 중앙값과 적합 건수를 정확히 계산합니다.
- 전세는 최대 보증금 하나로 비교합니다. 상한 이하 거래가 10건 이상이어야 추천 후보입니다. 주거비 점수는 전세 예산 적합 비율 60% + 전세 보증금 중앙값 대비 예산 여유 40%입니다. 월세 주거비 식과 표본을 섞지 않습니다.
- UI에서 월세/전세를 전환하고 월세 입력칸은 전세에서 숨깁니다. 각 유형의 예산을 따로 기억하며 전환 시 예산을 자동 환산하지 않습니다. 기준 위치·반경·중요도는 유지하고 이전 추천을 지워 유형이 다른 결과가 섞이지 않도록 했습니다.
- 기존 역 도보 모델, 서울 한정, 학교·직장 반경과 영역 결측 제외는 전세에도 동일하게 적용합니다.
- 전세가 없는 과거 스냅샷에는 월세로 대체하지 않고 전세 데이터 없음 안내를 표시합니다. 원천 테이블 구조는 그대로이며 JSONB 스냅샷의 신규 ID는 `-leases-walking`으로 기존 ID와 구분됩니다. Supabase 원격 적재는 아직 하지 않았습니다.

검증: 단위 테스트 28개 통과, 전세 보증금 3억원과 월세 보증금 1천만원/월세 65만원 TOP3의 적합 건수·전체 유형별 표본 수·중앙값을 각각 SQLite 원자료와 대조했습니다. 전세 0원 예산, 반경 결합, 최소 10건 경계, 거래 유형 분리와 과거 스냅샷도 검사했습니다. 전체 452개 도보 경로 검증도 유지됩니다.
